# Predicting NFL Tackle Locations: Temporal Composition, Interaction Structure, and Identity

Code and result files for the CMSAC 2026 submission. Every number, table, and
figure in the paper is produced by a file listed below.

Data: NFL Big Data Bowl 2024. The original Kaggle release was removed by the
host; the DVC pipeline downloads it automatically from the upstream GitHub
release. `src/prep_data.py` builds the prepared parquets from the raw download.

This repository builds on the SumerSports SportsTrackingTransformer study
(reference [3] in the paper). Its original README is preserved as
[`README_upstream.md`](README_upstream.md).

## Two source trees

The study was run as two lineages that diverged in `models.py` and were never
merged. Both are included verbatim so that each result is reproducible with the
code that actually produced it.

| tree | covers | STGNN class |
|---|---|---|
| `src/` | temporal architectures (S3.4, S4.2), feature ablations (S4.4), k-NN opponent sweep (S4.3) | `SpatioTemporalGNN` |
| `src_stgnn/` | topology probe and configuration sweep (S4.3), team and formation scheme arms (S4.4) | `STGNN_TS` / `STGNN_ST` |

They are not interchangeable: `src_stgnn/models.py` defines the winning
`knn_hybrid_hub` topology, which `src/models.py` does not, and the STGNN class
was renamed between them.

**Run every script from the repository root.** All paths in both trees are
resolved relative to the working directory (`data/`, `results/`, `models/`),
so invoking a script from inside `src/` or `src_stgnn/` will fail.

Both trees write checkpoints to `models/<model_type>/`. The type names do not
overlap between them (`hybrid_ts` etc. vs `stgnn_ts`/`stgnn_st`), so they
coexist; do not pass a `src/` model type to `src_stgnn/train.py` or the runs
will land in the same directory under different definitions.

## Reproducing

Dependencies are managed with [`uv`](https://docs.astral.sh/uv/getting-started/installation/).

```bash
uv sync
uv run dvc repro                 # downloads data, prepares it, trains, generates results
```

The DVC pipeline runs the full grid. To train a single temporal architecture:

```bash
uv run python src/train.py --model_type hybrid_ts --device 0
```

The topology work behind the headline result runs from the other tree; all three
stages take `--probe_device` to select a GPU:

```bash
uv run python src_stgnn/train.py --probe        --probe_device 0   # 11 topologies x 2 orderings
uv run python src_stgnn/train.py --knn_probe    --probe_device 0   # k sweep over hub topologies
uv run python src_stgnn/train.py --config_sweep --probe_device 0   # 5-seed sweep -> 4.077
```

Standalone ablations are run directly; the map above gives the script for each
arm. Figures and statistics are rebuilt with:

```bash
uv run python figures/scripts/cache_baselines.py    # naive baselines (needs data/, built by dvc repro)
uv run python figures/scripts/build_stats.py        # paired tests, BH correction
uv run python figures/scripts/epochs.py             # stopping-epoch analysis
uv run python figures/scripts/make_figures.py       # all figures
```

Monitor training with `uv run tensorboard --logdir models/`.

`build_stats.py`, `epochs.py` and `make_figures.py` read only the result files
committed here and run without the raw data; `cache_baselines.py` needs the
prepared tracking data.

Note on output locations: the ablation scripts write their summary CSVs under
`results/`, while the three shipped at the repository root
(`graph_knn_experiment.csv`, `gamestate_experiment.csv`,
`physical_experiment.csv`) are the copies `build_stats.py` reads. If you re-run
those arms, copy the regenerated CSVs to the root before rebuilding the stats.

Training recipe is identical across every experiment: AdamW, lr 1e-4, batch 256,
dropout 0.3, SmoothL1Loss, early stopping patience 10, max 200 epochs.
